# vibememory.ru

Лендинг VibeMemory — статический сайт на Astro.
Русский — базовый язык по адресу `/`, английский — по адресу `/en/`.

## Сборка

```bash
bun install
bun run dev       # разработка, http://localhost:4321
bun run build     # статическая сборка в dist/
bun run preview   # просмотр собранного dist/
bun run check     # типы (astro check), сборка и гейт локализации (bun test)
```

Результат — папка `dist/`: HTML, CSS, шрифты и иконки.
Внешних запросов у страницы нет: шрифты лежат в сборке, трекеров и CDN нет.

## Что где

- `src/pages/` — страницы: `index.astro` (ru) и `en/index.astro` (лендинги), журнал изменений
  (`changelog/…` и `en/changelog/…`: архив, страница записи и статический `index.json.ts` с тем же адресом `changelog/index.json`)
- `src/changelog/records.ts` — единый источник записей журнала: метаданные и ключи каталога, тексты лежат в `ru.json` и `en.json`
- `src/components/` — секции страницы, `Landing.astro` собирает их по порядку
- `src/layouts/Changelog.astro` — оболочка страниц журнала: свой head с canonical и hreflang страницы, slim-шапка с переключателем языков
- `src/components/Pain*.astro` — три анимированные сцены: агенты, команда, сессия на другом компьютере
- `src/locales/ru.json`, `en.json` — все строки интерфейса, плоские ключи с точками
- `src/i18n/` — подключение каталогов к переводчику каркаса
- `src/config/` — ссылки на кабинет, список агентов, тарифы, языки
- `src/scripts/` — клиентский JS сайта: выбор агента и копирование команды, сцена сессии; появление и язык — из каркаса
- `src/styles/theme.css` — палитра и шрифты кабинета поверх базовых стилей каркаса
- `tests/locales.test.ts` — гейт локализации каркаса со словарём данных сайта
- `tests/changelog.test.ts` — журнал изменений: JSON-контракт совпадает с каталогами и страницами,
  на лендинге ровно три записи и кнопка «Ещё», архив и записи есть в обоих языках, ссылок на закрытый репозиторий нет

## Журнал изменений

Репозиторий кода закрыт, поэтому «что нового» — публичные страницы сайта, а не релизы GitHub.

- На лендинге внизу — три последние записи, клик ведёт на страницу записи, кнопка «Ещё» — в архив
- Адреса: архив `/changelog/` и `/en/changelog/`, запись `/changelog/<id>/` и `/en/changelog/<id>/` (id — semver выпуска)
- Статический JSON по адресу `/changelog/index.json` — единый контракт с CLI, тот же источник, что и страницы:

```json
{
  "records": [
    {
      "id": "0.13.3",
      "date": "2026-10-25",
      "url": "/changelog/0.13.3/",
      "ru": { "title": "…", "summary": "…", "details": ["…"] },
      "en": { "title": "…", "summary": "…", "details": ["…"] }
    }
  ]
}
```

`records` отсортирован от новых к старым; `details` — полные пользовательские пункты без внутренних подробностей.
Новая запись: строки `changelog.<id>.*` в обоих каталогах, элемент в `ORDER` и `changelogKeys` в `src/changelog/records.ts`.

## Каркас

Общее у сайтов семейства — в пакете [SiteKit](https://github.com/VibeBrains/SiteKit) (`@vibebrains/site-kit`):
языки и переводчик, гейт локализации, базовые стили, `Base`, `Header`, `Footer`, `Lines`, `FusedLine`, клиентские скрипты, выкладка.
Здесь — то, что делает сайт собой: секции, сцены, тексты, тема.
Пакет закреплён тегом в `package.json`; обновление — новый тег там и `bun install`.

## Правила текстов

Одна строка каталога — одно предложение, в разметке строки выводятся отдельными блоками.
Точки в конце предложения нет, предложение не длиннее 160 символов.
Текст в разметке и в доступных именах (`aria-label`, `alt`, `title`) — только из каталога.

Гейт проверяет:
одинаковые ключи и подстановки в `ru.json` и `en.json`;
строй строк;
что каждый ключ используется;
что ни в исходниках, ни в собранных страницах нет текста мимо каталога.

## Анимации

CSS и SVG, немного JS.
Зацикленные сцены играют, только пока видны на экране.
При `prefers-reduced-motion: reduce` анимаций нет: сцены показывают итоговое состояние.

## Выкладка

`./deploy.sh` (через `site-deploy` каркаса) собирает сайт и кладёт его на хост продукта в `/srv/vibememory/site/<коммит>`.
Ссылка `current` переключается одним переименованием: посетитель не видит полсайта.
Три последние сборки остаются для отката руками.
Выкладывается только закоммиченное.
Caddy отдаёт `current` на `vibememory.ru`, а `/mcp` — серверу памяти.
Блок сайта живёт в репозитории продукта, `infra/Caddyfile.tmpl`, и ставится его `infra/caddyApply.sh`.
