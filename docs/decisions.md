Цель: видеть, откуда приходят и на какие кнопки нажимают; личных текстов на лендинге нет, полей ввода нет

### Где живёт код

Вопрос: копия в каждом лендинге или общий компонент
Выбор: `components/Metrika.astro` в SiteKit 0.3.0, сайт передаёт номер, ссылку на политику и тексты плашки из своего каталога
Причина: три лендинга владельца, правило «без согласия ничего не грузить» не должно разъезжаться; логика проверена юнит-тестами SiteKit
Следствие: сайт перешёл с SiteKit 0.1.0 на 0.3.0

### Где задаётся номер счётчика

Выбор: `metrika.counterId` в `src/config/site.ts`, пусто по умолчанию
Причина: лендинг статический, настроек на сервере нет; номер не секрет, смена номера — правка строки и выкладка
Пусто — Метрика не рисуется вовсе: нет плашки, скрипта и запросов к `mc.yandex.ru`; проверяет `tests/metrika.test.ts`

### Согласие

Выбор: плашка «Согласен» / «Только необходимые», решение в cookie первой стороны `vibememory_cookies` на год, «Настройки cookie» в подвале
Тег грузится только после «Согласен»; отказ после согласия стирает `_ym…` и перезагружает страницу без счётчика
Тексты плашки лежат в каталогах `ru` и `en` (`cookie.*`), гейт локализации их проверяет
Политика: `app.vibememory.ru/policy`, раздел 3 «Файлы cookie», абзац про Метрику

### Цели

## Публичный журнал изменений 26.10.2026

Цель: показывать пользователям, что нового в программе, при закрытом репозитории кода — страницы сайта вместо релизов GitHub

### Где живут записи

Вопрос: где единый источник текстов журнала
Выбор: каталоги `ru` и `en` (`changelog.<версия>.*`), метаданные и ключи — в `src/changelog/records.ts`
Причина: гейт локализации уже следит за паритетом языков и стилем строк, а лендинг обязан показывать
тексты из каталога; одно место на язык вместо дубля «каталог + данные»
Следствие: JSON `/changelog/index.json` для CLI собирается из тех же каталогов, тест `tests/changelog.test.ts`
сверяет JSON, каталоги и собранные страницы между собой

### Публичные страницы, не GitHub

Выбор: лендинг показывает три последние записи, архив — `/changelog/` и `/en/changelog/`, каждая запись —
`/changelog/<id>/` и `/en/changelog/<id>/`; ссылок на репозиторий кода нет, тест это держит
Причина: репозиторий VibeMemory закрыт, а релизы на GitHub есть только у публичных агентов семейства (VibeIDE, VibeIDEA)
Следствие: у страниц журнала своя оболочка (`src/layouts/Changelog.astro`): `Base` каркаса ставит canonical
и hreflang на адреса лендингов, для страниц журнала они должны вести на саму страницу и её перевод
